# SystemVerilog constraints (deep RAG)
# Curriculum map: https://chipverify.com/systemverilog/systemverilog-constraints
# Original ChipSutra wording. Prefer user DUT legal space over examples.

## Why constraints (CRV vs directed)
- Directed: hand-set every field — great for known bugs; does not scale.
- Unconstrained random: wasteful illegal/uninteresting traffic; misses corners.
- Constrained-random: solver picks values inside legal bounds; many seeds → corners.
- ChipSutra: pure SV class + `randomize()`, or UVM `sequence_item` with same rules.

## rand vs randc
- `rand`: independent draw each call (repeats allowed).
- `randc`: cyclic — exhaust value space before repeat (good for opcode/addr sweeps).
- Without `rand`/`randc`, `randomize()` ignores the field.
- Prefer `randc` for small enums that must all appear; `rand` + coverage for large spaces.

## Constraint block basics
- `constraint name { expr; expr; }` — all exprs AND'd.
- Separate named blocks → enable/disable per test via `constraint_mode(0|1)`.
- Always check: `assert(obj.randomize()) else $fatal(1, "randomize failed");`
- Failed solve leaves prior values; never ignore return code.
- Over-constrained / contradictory constraints → solve fails (fix the constraints).

## Common expressions
- Relational: `addr >= 8'h10; data < 32'h1000;`
- `inside`: `opcode inside {READ, WRITE}; size inside {[4:64]};`
- Negation: `!(opcode inside {RSVD});`
- Alignment: `addr[1:0] == 2'b00;` (AXI word-aligned smoke)
- Implication: `(cmd == READ) -> (wstrb == 0);` — RHS only when LHS true
- Equivalence when needed: `(mode == BURST) <-> (len > 0);` sparingly

## Weighted dist
- Bias traffic: `cmd dist { READ := 70, WRITE := 30 };`
- `:=` weight per listed value; `:/` splits weight across a range.
- Use dist for realism (mostly reads) without forbidding rare writes.
- Soft preference: soft constraints or dist — don't hard-forbid rare legal cases needed for coverage.

## Soft constraints and overrides
- `soft { idle_cycles inside {[0:3]}; }` — overridable by hard constraints / inline.
- Inline one-shot: `assert(pkt.randomize() with { addr == 8'hFF; });`
- Subclass constraints add/override; keep base class legal-by-default.
- `rand_mode(0)` to freeze a field; restore with `rand_mode(1)`.

## Arrays, foreach, solve before
- Dynamic/queue/array: `constraint c_size { data.size() inside {[1:8]}; }`
- Element rules: `foreach (data[i]) { data[i] inside {[0:255]}; }`
- Ordering hint: `solve len before data;` when size depends on len (helps solver).
- Unique: `unique { a, b, c };` for distinct IDs/ports when required.

## pre_randomize / post_randomize
- `function void pre_randomize();` — set knobs, enable/disable constraints, compute sizes.
- `function void post_randomize();` — derive parity, checksum, non-rand mirrors.
- Do not put DUT golden updates inside randomize hooks; keep hooks for txn shaping only.

## Disable / mode control patterns
- Per scenario: disable `error_inject_c` for smoke; enable for fault tests.
- Plusargs: if ($value$plusargs("BURST_ONLY=%d", b) && b) pkt.idle_c.constraint_mode(0);
- UVM sequences: inline `with {}` for directed overlays on randomized base items.

## ChipSutra anti-patterns (constraints)
- Randomizing DUT outputs or reset every cycle without intent.
- Contradictory hard constraints (e.g. `x > 255` on 8-bit).
- Ignoring `randomize()` failure → stale stimulus looks like DUT bugs.
- Constraints that invent protocol fields not in user RTL.
- Hardcoding DEPTH/WIDTH that disagree with DUT parameters.

## Minimal txn sketch (any DUT inputs)
```
class txn;
  rand logic [W-1:0] data;
  rand bit           valid;
  constraint legal_c { soft valid dist {1 := 3, 0 := 1}; }
endclass
```
Map `rand` fields only to signals the TB drives; widths from parsed RTL.
