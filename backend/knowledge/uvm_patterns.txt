# UVM / SV testbench patterns (RAG). Prefer user RTL ports over invented names.

## Verilator-friendly randomized SV TB (DEFAULT)
- Prefer pure SystemVerilog over full UVM for local Verilator runs.
- Exact DUT port map: `dut_name dut ( .clk(clk), .rst_n(rst_n), ... );`
- Prefer **one random loop** with a golden model — not hardcoded Testcase 1..N lists.
- Driven TB signals: `reg`/`logic`. Include `$dumpfile`/`$dumpvars`/`$finish`.
- Clock MUST be: `always #5 clk = ~clk;`
- Golden MUST be independent (`expected`), never `exp = count + 1`.
- Keep ~45–70 lines. Forbidden: invented ports; chatty preamble; unrolled assert walls.

## Counter enable example (copy structure)
```systemverilog
`timescale 1ns / 1ps
module counter_rtl_tb;
  logic clk, rst_n, enable;
  logic [3:0] count;
  logic [3:0] expected;
  integer i, errors;
  counter_rtl dut (.clk(clk), .rst_n(rst_n), .enable(enable), .count(count));
  always #5 clk = ~clk;
  initial begin
    $dumpfile("counter_rtl_tb.vcd"); $dumpvars(0, counter_rtl_tb);
    errors = 0; void'($urandom(1));
    clk = 0; rst_n = 0; enable = 0;
    repeat (4) @(posedge clk); rst_n = 1; @(posedge clk);
    expected = '0;
    for (i = 0; i < 48; i = i + 1) begin
      enable = $urandom_range(0, 1);
      @(posedge clk); #1;
      if (enable) expected = expected + 1'b1;
      if (count !== expected) begin
        $error("mismatch"); errors = errors + 1;
      end
    end
    $finish;
  end
endmodule
```

## UVM (only when user asks / methodology=uvm)
- Hierarchy: test → env → agent (sequencer, driver, monitor) → scoreboard/coverage.
- Item: `uvm_sequence_item` with rand fields matching DUT-driven inputs.
- Driver: `get_next_item` → drive pins → `item_done`. Sequence: `start_item`/`finish_item`.
- Monitor: sample pins → `ap.write(txn)`. Scoreboard: analysis imp/fifo compare vs predict.
- config_db for virtual interface; factory `type_id::create`; `` `uvm_component_utils ``.
- Top: instantiate DUT + IF, `uvm_config_db::set`, `run_test();`.
- MUST emit `interface <dut>_if` (virtual if is not a type without it) and `uvm_sequencer#(txn)`.
- connect_phase: `drv.seq_item_port.connect(sqr.seq_item_export);` `mon.ap.connect(sb.imp);`
- Legal SV: `virtual function void` / `virtual task` — NEVER `virtual void` or `endprotected`.
- Monitor extends `uvm_monitor` + `analysis_port.write`. Subscriber is for scoreboard/coverage only.
- Sequence: `class <dut>_seq extends uvm_sequence#(txn); task body();` — never `uvm_sequence#(T) seq = new()`.
- Scoreboard: `uvm_analysis_imp` + `write()`. Never `seq_item_port.get`. Reset is `rst_n`, not `enable==0`.
- Forbidden fake APIs: `.put()`, `.configure(vif)`, `cast(rhs)`, `driver.start(this)`.
- Forbidden TLM: `seq_item_port.connect(monitor.analysis_export)` / agent port to scoreboard.

## UVM phases (deep)
- build (top-down) → connect (bottom-up) → end_of_elaboration → start_of_simulation
  → run (time) → extract → check → report → final.
- Construct children in `build_phase`; TLM connects in `connect_phase`.
- Always `super.phase(phase)` when overriding.
- Phase lifecycle map (build/run/cleanup + sub-phases): `uvm_phases.txt`.
- End-of-test: raise/drop objections in run_phase — details `uvm_objection.txt` (or default sequence + drain).

## UVM reporting
- `` `uvm_info(ID, msg, verbosity) `` / `` `uvm_warning `` / `` `uvm_error `` / `` `uvm_fatal ``.
- Prefer these over bare `$display` in UVM components; filter via plusargs/verbosity.
- Fatal on null vif / failed config_db get.

## UVM factory & overrides
- Create via factory so tests can `set_type_override` / `set_inst_override`.
- Use overrides for error-injector driver variants — don't edit base VIP.
- Register types with utils macros or risk silent create failures.

## UVM TLM paths
- `uvm_analysis_port` → `analysis_export` / `analysis_imp` / `tlm_analysis_fifo`.
- Non-blocking monitor→scoreboard; blocking put/get ports for sequencer↔driver (seq_item_pull).
- Do not replace UVM TLM with ad-hoc mailboxes unless pure SV layered TB.
