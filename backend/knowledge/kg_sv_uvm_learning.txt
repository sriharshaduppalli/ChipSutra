# ChipSutra SV / UVM Knowledge Graph (RAG)
# Chunked by ## for continuous LLM learning. Prefer user RTL over examples.

## KG overview — verification learning spine
ChipSutra verification knowledge is a directed graph: SV language → OOP/random → UVM → reuse/scalability → testcase strategy → inbuilt functions/constructs.
Learning order (L1→L4): syntax → stimulus/check → architecture → closure/scale.
Always: exact DUT ports; Verilator-friendly SV by default; UVM/OVM/VMM only when methodology asks; independent golden models (never exp=count+1).
External curriculum map (study order): ChipVerify SV + UVM tutorials — https://chipverify.com/tutorials/systemverilog — also see verification_methodologies_curriculum.txt (methodologies ladder).
MUST-KNOW pillars (every generate): data types, arrays/collections, control-flow loops,
classes/OOP, randomization, constraints, covergroups, assertions/SVA, interfaces, threads/IPC —
see sv_fundamentals_must_know.txt and matching sv_*_patterns.txt / covergroup_patterns.txt / sva_patterns.txt.

## Methodology selection — SV / UVM / OVM / VMM
- User picks methodology; do not silently swap UVM for pure SV (or the reverse).
- Ladder: Vera/e (hist) → VMM → OVM → UVM (IEEE 1800.2). ChipSutra ids: sv|uvm|ovm|vmm.
- sv: module TB, clock/reset, $urandom or class CRV, independent golden, dump/$finish.
- uvm: real uvm_* agent/env/test + config_db vif + start_item/finish_item / get_next_item/item_done.
- ovm: legacy ovm_* only; compact env; comment methodology=ovm.
- vmm: legacy channel/xactor style; comment methodology=vmm.
- UVM architecture/RAL/TLM smoke vs advanced: `uvm_users_guide_emit.txt` (Accellera UG 1.2 concepts, original wording).
- Mix OVM+VMM only if the user asks: interconnected adapters (`ovm_vmm_interop_emit.txt`); never wrap/hide VIP; never mix uvm_* with ovm_*.
Forbidden: mixing uvm_* with ovm_*; fake UVM APIs; inventing CSR RAL without a map; emitting Accellera UBus as a protocol.

## L1 — Standard SystemVerilog syntax (must know)
- Modules, ports (input/output/inout), parameters/localparams, generate, packages, imports.
- Data types: logic, bit, reg, wire, int, integer, enum, struct, union, packed/unpacked arrays, queues ($), associative arrays.
- Procedural: always_ff / always_comb / always_latch; initial; forever; fork/join(_any|_none).
- Timing: #delay, ##cycle (SVA), @(posedge/negedge), wait, event.
- Operators: logical/bitwise/reduction/concat/replicate; ===/!== vs ==/!=; inside; streaming.
- Interfaces + modports; virtual interfaces in TB/UVM.
- Tasks/functions (automatic); void'(); $cast; type().
- Deep refs: sv_datatypes_control_patterns.txt, sv_arrays_collections_patterns.txt, sv_oop_classes_patterns.txt.
Forbidden in TB codegen: inventing ports; chat prose after endmodule; broken clocks (use always #period clk=~clk).

## L1 — SV constructs for testbenches

- DUT instance with named port map only.
- Stimulus drivers vs monitors; scoreboard/reference model; checkers.
- Assertions: immediate assert; concurrent assert/assume/cover property; bind.
- Coverage: covergroup/coverpoint/bins/cross/illegal_bins/ignore_bins.
- VCD: $dumpfile/$dumpvars; end with $finish/$stop.
- Random: $urandom, $urandom_range, std::randomize, rand/randc, constraint, soft, unique, solve before.

## L1 — Inbuilt functions and system tasks (TB-critical)
- Random: $urandom, $urandom_range, $random (legacy), srandom/process::self.srandom for seeds.
- Display: $display/$write/$sformatf/$time/$realtime; $error/$warning/$info/$fatal.

## L2 — Randomization techniques
- Directed-random: few directed resets/corners + random legal traffic (high value / low lines).
- Constrained-random: class with rand fields + constraints mirroring DUT legal space.
- Inline: std::randomize(a,b) with { a inside {[0:3]}; b < a; }.
- Distribution: dist { 0:=1, 1:=3 }; soft constraints for overridable knobs.
- Stability: seed via +ntb_random_seed / void'($urandom(seed)); log seed in TB.
- Coverage-driven: randomize until coverpoints hit; avoid unrolled Testcase 1..N walls.
- Counter pattern: enable=$urandom_range(0,1); expected independent; check count===expected each cycle.
- Deep reference: sv_constraints_patterns.txt (randc, implication, foreach, solve before, anti-patterns).

## L2 — Interfaces and clocking (TB connectivity)
- Bundle DUT pins in `interface` with `logic` (4-state); parameterize widths.
- `modport` views for DUT / TB / monitor; virtual interface + config_db for class/UVM.
- Clocking blocks for skew-safe drive/sample; pure SV smoke may skip IF and use named ports.
- Deep reference: sv_interfaces_patterns.txt.

## L2 — Reusable techniques (block → IP)
- Layer TB: clock/reset IF → driver → monitor → scoreboard → sequence library.
- Package shared types/enums/constraints; typedef transaction items once.
- Parameterize WIDTH/DEPTH/AGENT_KIND; avoid hard-coded magic numbers.
- Virtual interface + config_db (or simple SV handles) for connection.
- Callbacks/hooks for scoreboard predict/check; factory overrides for variants.
- Separate stimulus policy from checking (so sequences reuse across DUTs).
- Golden/reference model as pure function or class predict(txn) → expected.

## L2 — Reusable testcases vs extended testcases
- Base smoke: reset, idle, one legal transaction, dump, $finish (always keep green).
- Reusable library: reset_seq, random_traffic_seq, backpressure_seq, error_inject_seq.
- Extended tests: inherit/compose base sequences; add corners (full/empty, wrap, X, reset-during-traffic).
- Regression: seed list + plusargs (+SEED=, +N_TXN=, +TEST=); same binary, many seeds.
- ChipSutra mapping: Fast-random template = reusable smoke; LLM/UVM = extended agent/env when asked.

## L3 — UVM syntax and architecture
- Hierarchy: uvm_test → uvm_env → agents (sequencer/driver/monitor) → scoreboard/coverage.
- Objects: uvm_object / uvm_sequence_item; components: uvm_component with phases.
- Phases: build → connect → end_of_elaboration → start_of_simulation → run → extract → check → report.
- Config: uvm_config_db#(virtual if)::set/get; uvm_resource_db sparingly.
- Factory: type_id::create; set_type_override / set_inst_override for reuse.
- Sequences: uvm_sequence#(item); start on sequencer; start_item/finish_item; get_next_item/item_done on driver.
- TLM: analysis_port/export/imp/fifo for monitor→scoreboard.
- RAL: uvm_reg_block / reg / field; frontdoor/backdoor; predict/mirror.
Forbidden fake APIs: .put() as UVM, .configure(vif), cast(rhs), driver.start(this).

## L3 — UVM scalability techniques
- Multi-agent env with agent arrays; virtual sequencers for coordination.
- Layered sequences (bus → protocol → application).
- Scoreboard with associative arrays / queues keyed by ID/tag; out-of-order compare.
- Parallel tests via seeds + plusargs; split long tests into short reusable sequences.
- Register tests: hw_reset, bit_bash, mem_walk from RAL sequences (when CSR map exists).
- Vertical reuse: block agent reused in subsystem env; chiplet VIP stubs at boundaries.
- Performance: narrow logging (`UVM_LOW`), selective recording, disable heavy cover when smoke.

## L3 — UVM randomization and constraints
- rand/randc on sequence_item fields matching DUT ports/fields.
- constraint legal_c { addr[1:0]==0; len inside {[0:15]}; }.
- pre_randomize/post_randomize for derived fields; soft for defaults.
- uvm_sequence_item::randomize() or `assert(item.randomize())`.
- Constraint mode on/off for directed overlays; inline constraints in sequences.
- Seed control: +ntb_random_seed / uvm_cmdline; print seed in test.

## L4 — Scalability beyond single DUT
- Block → IP → SoC: same agent, richer virtual sequences; clock/reset domains.
- CDC-aware stimulus: don't assume same-cycle paths across async FIFOs.
- Power/DFT awareness: retention/isolation as constraints when UPF given (don't invent).
- Chiplet/D2D: treat links as VIP unless RTL ports given (UCIe/BoW concepts only).
- Coverage closure: hole → new constrained sequence → re-sim → merge coverage (ChipSutra coverage loop).
- Techniques: sim (ChipSutra default); formal on control/reset/security SVA; emulation for OS boot; FPGA proto for real cables. Not alternatives.
- Stages: block isolation (highest coverage) → subsystem interfaces → SoC end-to-end. Later stages do not replace earlier ones. Bug cost rises each stage.

## L4 — Quality gates for generated TB (ChipSutra)
- Exact DUT instance and port map from parsed RTL.
- Good clock: always #N clk=~clk; dump + $finish present.
- Golden independent of DUT outputs; randomized stimulus present.
- No invented ports; no essay after endmodule.
- Fail lint → fall back to verified skeleton template.

## Anti-patterns catalog (lint + RAG)
- Invented ports (`data_in`/`data_out`) when DUT has enable/count -> reject.
- Circular golden `exp = count + 1` -> reject; use independent `expected`.
- Broken clock `clk=~clk; forever @(posedge clk)` -> use `always #5 clk=~clk`.
- Unrolled Testcase 1..N assert walls -> one `$urandom` loop instead.
- Fake UVM APIs (`.put()`, `.configure(vif)`, `driver.start(this)`) -> real TLM only.
- Markdown essay after `endmodule` -> strip / regenerate.
- FIFO TB that only toggles wr_en without a queue model -> incomplete; add q[$] scoreboard.
- AXI TB that randomizes all s_axi_* every cycle without handshakes -> illegal; use AW+W then B, AR then R.
- AXI VALID that waits for READY before asserting -> deadlock; assert VALID independently, hold until handshake.
- AHB TB that drops HWRITE/HTRANS in the same timeslot as the address posedge -> writes never land; #1 after posedge, hold HWRITE through data phase.
- AHB TB that presents HWDATA on the address-phase cycle -> data belongs to the previous address.
- APB TB that changes PSEL/PENABLE/PADDR while PREADY is LOW in ACCESS -> illegal; hold until PREADY.
- Ignoring WIDTH/DEPTH parameters (hardcoding depth=16 on DEPTH=8 DUT) -> mismatch full/empty.

## Protocol goldens — competitive block smoke
- Counter: independent `expected` += enable (or +1 free-run); never expected=count+1.
- Sync FIFO (FWFT): queue mirror; clamp stimulus on full/empty; check empty/full/count/rd_data.
- Parity: `parity === ^data` when valid.
- AXI4-Lite slave (small aperture): model_reg[addr[3:2]]; complete B before next write; check RDATA.
- AHB-Lite slave: NONSEQ address phase then data phase; HWDATA on the data-phase cycle; independent mem model.
- APB slave: SETUP then ACCESS; hold controls while PREADY LOW; model_reg on completing write.
- Prefer Fast-random skeleton for these patterns; use LLM/UVM for agents, virtual sequences, RAL.

## AMBA emit rules (IHI 0022L / 0033C / 0024E — distilled, not copied)
- AXI: transfer only when VALID&&READY at posedge ACLK. Transmitter must not wait for READY before VALID; hold VALID until handshake. VALID LOW in reset. BRESP/RRESP OKAY=2'b00. Do not invent AXI5-only pins (BCOMP, credits, wakeup) unless RTL has them.
- AHB: 1-cycle address phase (cannot wait) overlapping previous data phase. HWDATA is data-phase. HTRANS NONSEQ for singles. After address posedge, #1 then change HWRITE/HTRANS.
- APB: SETUP then ACCESS; complete when PREADY=1. While PREADY=0 in ACCESS, hold PSEL/PENABLE/PADDR/PWRITE/PWDATA. PSTRB LOW on reads. PSLVERR valid only last ACCESS cycle.
- AXI4 burst / ACE / CHI: require user VIP. Do not use the Lite 4-reg golden when AWLEN exists. Do not invent snoop or CHI flit timing.
- Serial knobs: SPI mode 0–3 from user CPOL/CPHA; I2C master vs 7/10-bit; UART RX baud_div from user — never invent baud.
- CAN/I3C: idle/SOF smoke or I2C-compatible fallback. CCC/IBI/bit-time only with user ports or knobs.
- Scale: block=pin smoke; ip=reusable agent+user RAL; processor=ISA+maps; subsystem/SoC/chiplet=user topology only.
- Off-chip / D2D / DRAM / net I/O: PCIe CXL UCIe DDR Ethernet USB MIPI are VIP-bound — never invent timings.
